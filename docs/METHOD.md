# 路径成本与算法

## 状态

每个路口有四种车头状态 N/E/S/W；N 对应 +y，E 对应 +x。沿某条道路到达下一个节点时，车头变为该道路的方向。

只用路口作为状态会丢失入射方向；两条路径即使到达同一路口，后续转向代价也可能不同。Python 使用堆实现 Dijkstra，C 与浏览器使用有界状态扫描。它们求解同一个非负整数成本图。

## 成本

```text
travel_ms = ceil(length_mm × 1000 / speed_mm_s)
turn_ms = 对应左转/右转/掉头标定耗时 + settle_ms
          直行时为 0
risk_cost_ms = ceil(risk_permille × risk_penalty_ms / 1000)

distance: length_mm
fastest:  travel_ms + turn_ms
robust:   travel_ms + turn_ms + risk_cost_ms
```

`risk_permille` 在演示与随机实验中是人为设定的道路风险分数。风险项是软代价，并非硬概率约束；它可能反复累计。报告中的 `1 - ∏(1-risk/1000)` 只在假设边事件独立时成立，不能当作测得的真实失败概率。

所有策略先做同一通行检查：道路未阻塞，而且 `width_mm >= vehicle_width_mm + 2 × clearance_mm`。宽度足够仍不能证明小车的完整扫掠轨迹在路口转向时不碰边，后续需要几何与实车检查。

## 模型假设

- 已知路口拓扑；当前版本没有自动建图或 SLAM。
- 仅支持横向、纵向路段；存在中间路口时必须拆分边。
- 各道路的长度是独立属性，绘图坐标仅表达拓扑。
- 转弯在路口按设定动作完成，直线匀速；没有建模加减速、轮胎打滑或运动中的连续曲率。
- 图在一次规划调用中保持稳定。地图版本改变后必须丢弃旧执行计划。
- 起点车头已知；末端朝向约束尚未加入成本搜索。

## 有界嵌入式实现

最多 64 个节点、256 条有向边、256 个方向状态。C 不使用 malloc，工作区由调用方提供，宜放在静态区。用 uint32_t 保存成本，参数边界限制路径成本的最坏范围。结果包含每段动作和地图版本。

当前本机测得工作区 2304 字节、图结构 2568 字节、路线结果 6164 字节。总计约 11KB，且不包含传感器、通信、控制环、栈或 MCU 运行库开销。小内存板可以减小宏上限，并重新编译、测试结构大小。

算法按有限状态扫描求解，复杂度包含状态扫描和道路扫描，适合本项目的小拓扑图。当前阻塞处理从已确认状态重新运行 Dijkstra，**没有实现 D* Lite 或增量搜索**。

## 特色与研究范围

本项目把方向相关的动作成本、道路有效性和执行前提放在同一条可核验链路中。三个语言版本的严格一致性使浏览器所见的路径可以对应到嵌入式算法。

方向状态图与多项加权成本都是已有方法。本项目属于面向电赛练习的工程实现，不声称提出新的最优路径理论。
