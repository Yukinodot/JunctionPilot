# 硬件接口、连线与标定

当前提供可移植算法与接入说明，没有完成 PCB、厂商 HAL 工程、MCU 交叉编译、烧录或实车测量。以下是一套练习平台接口方案，具体端口号应依据你实际开发板引脚复用表分配。

## 建议平台组成

| 部件 | 需要提供的功能 | 接入方式 |
|---|---|---|
| MCU 开发板 | 定时器、PWM、编码器或中断输入、串口 | 可考虑 MSPM0G3507 或已有 STM32 板；具体电赛器件约束按赛题确认 |
| 双路电机驱动 | 左右轮的方向与 PWM | MCU 控制端接驱动逻辑输入，电机接桥输出 |
| 双电机差速底盘与编码器 | 距离/速度估计 | 编码器信号接 MCU 计数输入 |
| 灰度/循迹传感器阵列 | 线位置和路口识别 | 模拟型接 ADC，数字型接 GPIO；阈值需在实际地面标定 |
| IMU，可选 | 转弯角度与漂移检查 | I²C/SPI，按器件逻辑电平连接 |
| 测距模块 | 前方障碍事件 | 串口、I²C 或触发/回波输入，取决于实际模块 |
| 视觉识别模块，可选 | 外部目的标号与置信度 | UART 向 MCU 发送已定义的识别消息 |

MSPM0G3507 的厂商资料给出 128KB Flash、32KB SRAM：[TI 产品页](https://www.ti.com/product/MSPM0G3507)。本项目最大数组配置合计约 11KB，但仍需预留其他模块和栈。若使用更小存储型号，应减小节点与路径上限。

驱动例子 DRV8833 的电机供电范围为 2.7–10.8V：[TI 产品页](https://www.ti.com/product/DRV8833)。电机堵转电流、模块散热能力与实际电池电压要根据所选型号核对，不能把该芯片的宣传峰值电流直接视作整块模块持续能力。

## 信号连接关系

```text
电池/供电模块 ── 电机驱动 VM ── 左右电机
       └──── 稳压后的开发板电源

MCU 左轮 PWM/方向 ── 驱动左通道逻辑输入
MCU 右轮 PWM/方向 ── 驱动右通道逻辑输入
MCU ADC/GPIO     ── 循迹传感器阵列
MCU 编码器输入   ── 左右轮编码器 A/B（按输入能力配置）
MCU I²C/SPI      ── IMU（可选）
MCU UART/测距输入 ── 障碍检测模块
MCU UART         ── 外部识别模块

以上模块信号地共地；供电和逻辑电平按各模块资料匹配。
```

该图表示接口关系，不是已经完成并验证的电路原理图。当前没有指定某块板的 GPIO 号码，避免把主机程序当作可直接烧录的完整固件。

## 接入顺序

1. 先移植 `jp_planner.c/.h` 和 `jp_guard.c/.h`，把工作区、地图和路线结果放在静态区。
2. 用 `export_firmware.py` 生成地图结构，把实际路线长度/宽度填入地图。
3. 完成独立的电机、循迹、转弯和路口检测模块，先验证单段运动。
4. 在已确认路口调用 `jp_plan`，输出动作进入控制状态机。
5. 执行 LEFT/RIGHT/UTURN，确认角度和线路后进入 FOLLOW；到达下一路口后确认节点与车头。
6. 每个控制周期调用运动许可检查；HOLD 必须实际输出零 PWM，并保持停车锁定。
7. 新计划和新定位确认后调用 `jp_guard_arm`，再恢复任务。

规划调用不要放在高频电机中断中。中断更新传感器快照，上层任务读取一致快照、更新地图版本和处理规划。

## 标定记录

`configs/calibration.example.json` 中数值是仿真初值。至少记录：

| 参数 | 测量方法 | 应保存的证据 |
|---|---|---|
| speed_mm_s | 测量已知直线距离的稳定段时间；重复多次 | 距离、时间、负载、电池电压 |
| left_ms/right_ms | 分别执行 90° 转弯，并计到重新稳定循迹 | 方向、角度误差、完成时间分布 |
| uturn_ms | 180° 掉头到可继续循迹 | 角度误差、耗时、丢线次数 |
| settle_ms | 从角度动作结束到线路误差稳定 | 恢复时间、稳定判据 |
| vehicle_width_mm/clearance_mm | 量车宽，检查实际转弯扫掠空间 | 车体尺寸、最窄走廊、转向录像 |
| risk_permille | 根据某路段的重复实测失败次数建立代理分数 | 样本量、失败定义、置信区间 |

循迹控制器本身需要速度环与线偏差环标定；当前没有用规划仿真替代这些测试。
